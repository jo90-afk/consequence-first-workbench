# Experience coherence audit

## Model fidelity

- Are semantically different objects visually or behaviorally distinguishable?
- Does the interface preserve dependency direction and state status?
- Are false or superseded items excluded from active views while remaining inspectable in history?
- Does the interface introduce prerequisite knowledge before dependent material?
- Are evidence and commentary traceable without being mistaken for the primary claim or text?

## Attention

- Does the first view answer what changed, where the user is, or what requires action?
- Is urgency derived from consequence and timing rather than color or motion alone?
- Does a large change receive synthesis before detail?
- Can settled background state recede without disappearing from the model?
- Are warnings actionable, or are they transferring interpretation back to the user?

## Action

- Is the relevant action visible when it becomes available?
- Does the control’s label describe the action in the current state?
- Does completion update the underlying state and remove obsolete work?
- Can users record notes or context where ongoing work requires it?
- Are destructive or externally consequential actions clearly bounded and authorized?

## Spatial and visual meaning

- Does spatial position encode a relation the user can learn and reuse?
- Are frame, size, color, density, and connection applied consistently?
- Is the primary material given the majority of the useful surface?
- Have decorative frames or skeuomorphic containers reduced usable space?
- Does every persistent element justify the attention it consumes?

## Responsive behavior

- Do mobile and desktop expose equivalent capability and accessibility?
- Does reflow preserve reading, editing, or map position?
- Do persistent controls overlap menus, content, keyboard regions, or one another?
- Does real dense content remain usable at target breakpoints?
- Are supporting layers transformed or collapsed before primary work becomes cramped?

## State coverage

Inspect at least the states affected by the request:

- first use and orientation;
- populated normal use;
- large or catastrophic change;
- empty and completed state;
- uncertain or contradictory data;
- loading, failure, and unavailable integration;
- historical or superseded state;
- return after navigation, reflow, or session change.

## Coherence test

Ask a user-facing question for every prominent element: “What can I understand or do because this is here?” Remove or demote elements that only expose implementation structure.

The interface is coherent when the model produces stable meaning, current action, and inspectable provenance without requiring the user to reconstruct the system’s logic.
