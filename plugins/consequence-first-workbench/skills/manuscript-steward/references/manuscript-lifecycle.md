# Manuscript lifecycle

## Unit states

Use only the states the project needs, but preserve these distinctions:

- **planned** — scope or argument exists without prose;
- **drafting** — prose is being created;
- **review** — a specific candidate is before the author;
- **revision** — feedback is being incorporated;
- **approved** — the author accepted a specific candidate and stated corrections;
- **incorporated** — the approved candidate is present in the canonical manuscript;
- **superseded** — a later approved revision replaced the unit while history remains traceable.

Approval and incorporation are separate. A chapter can be approved while the file update is still pending; it is not incorporated until verified in the canonical artifact.

## Minimal unit record

Track in the project’s existing state mechanism:

- stable unit identity and current title;
- structural destination;
- candidate version or fingerprint;
- current lifecycle state;
- approval statement and accepted corrections;
- incorporation version and location;
- dependencies on prior or later units;
- unresolved substantive or source questions;
- superseded unit when applicable.

Do not create a separate ledger when document properties, a database, project state, or an established manifest already records this information.

## Draft-to-incorporation flow

1. Recover the outline, settled argument, prior approved units, and current unit purpose.
2. Draft or revise the unit without editing the canonical manuscript.
3. Present the complete candidate for review in the requested form.
4. Apply feedback while preserving propositions the user did not reject.
5. Record explicit approval of the exact candidate or corrected candidate.
6. Open the canonical manuscript and confirm its identity and current state.
7. Insert the approved unit at its structural destination.
8. Update contents, cross-references, numbering, metadata, and state records affected by the insertion.
9. Verify text, ordering, document structure, and rendered pages.
10. Advance the canonical version and start the next unit from that state.

## Continuing work

Interpret common instructions carefully:

- **“Approved. Continue.”** Incorporate the current unit, verify it, then begin the next unit.
- **“Better; clean it up later. Approved.”** Preserve the deferred cleanup as a bounded editorial task, incorporate the accepted current content, and avoid reopening substance during the later pass.
- **“Fix before moving on.”** Revise the candidate and return it for approval unless the user explicitly approved the corrected result in advance.
- **“Do it.”** Resolve the referent from visible context; do not treat it as chapter approval when it authorizes a different operation.

## Revising approved material

When the user requests a later change:

1. identify every approved unit materially affected;
2. preserve the accepted thesis and surrounding dependencies;
3. draft the smallest coherent forward revision;
4. obtain approval when the project uses approval gating;
5. incorporate and record supersession rather than overwriting history silently.

Broad editorial passes may revise many approved units only when the user authorizes that scope. Keep substantive reinterpretation separate from cleanup unless the request combines them.

## Version reconciliation

When manuscript copies conflict, establish the canonical baseline before editing. Treat older copies as history or recovery sources. Recover missing material as an explicit forward candidate and verify it against later approved decisions before incorporation.
